# 2026 灯具设计师理论题库 · 刷题站

2026 年全国行业职业技能竞赛——第五届全国工业设计职业技能大赛「灯具设计师」赛项理论试题库的刷题站。纯静态页面，原生 HTML + CSS + ES Modules，**零依赖、零构建**，直接部署到 GitHub Pages 仓库根目录即可使用。

**线上地址：<https://peng684596.github.io/lamp-2026-quiz/>**

## 本地预览

```bash
cd lamp-2026-quiz
python -m http.server 8123
```

然后浏览器打开 <http://localhost:8123/>。

不要直接双击 `index.html`：页面用 `fetch` 加载题库，`file://` 协议下会被浏览器的安全策略拦截。任意静态文件服务器都可以，不要求 Python。

## 功能

- **首页**：可练题数、已练题数、今日待复习、错题本数量四个数字卡；快捷入口；章节进度条；连续打卡。
- **章节练习**：八章卡片入口，逐题作答。单选/判断点击即判，多选点「提交答案」判定，**全对才得分**，漏选多选都算错。
- **模拟考试**：范围（全部或指定章节）、题量（20/50/100/全部）、时长（30/60/90/120 分钟）可配；倒计时最后 60 秒变红，时间到自动交卷；答题卡支持跳题与标记；交卷后按题型拆解正确率并逐题回顾。
- **错题本**：答错自动收录，可按章节/题型筛选，支持连续答对提示、单题标记「已掌握」、清空与整体重练。
- **收藏**：练习中一键 ★ 收藏，集中重练。
- **记忆曲线**：简化 SM-2（1/2/4/7/15/30 天间隔），按等级从低到高安排今日复习。
- **统计**：累计答题与正确率、连续打卡、近 14 天答题量柱状图、各章节正确率、考试历史（最多 20 条）。
- **设置**：选项乱序（默认开）、自动下一题（默认关）、主题跟随系统/浅色/深色、包含重复题（默认关）、数据导出/导入/清空。

答题记录、错题、收藏、设置、统计与未完成的考试都保存在浏览器本地（`localStorage`，未完成考试在 `sessionStorage`），刷新不丢；不上传任何数据，换浏览器或清空站点数据会丢失，请用设置页的导出功能备份。

选项乱序是确定性的：按题目 id 与会话盐做 seeded shuffle，回看同一道题顺序不变；判断题永不打乱；判分始终映射回原始选项 key。

## 题库数据

`data/questions.json` 为运行时唯一数据源（700 条，全部可练）。前端不写死题数、章节名或题目内容——**替换题库只需把同样 schema 的 JSON 覆盖到 `data/questions.json`，代码无需任何改动**。数据契约见 `docs/SPEC.md` 第 1 节。

三个大题的题号各自从 1 开始，所以界面上显示为 `单071 · P10` 这样的组合：题型简称 + 三位题号 + PDF 页码，方便对着原始 PDF 核对。

## 从 PDF 重新生成题库

```bash
python tools/extract.py "4.2026灯具设计师赛项理论试题库(1).pdf"
python tools/parse.py
python tools/build.py
```

- `tools/extract.py`：用 PyMuPDF 按视觉坐标重建文本行（该 PDF 的文字流顺序与视觉顺序不一致，选项字母和文字被拆在不同 block，直接按流读取会错行），同时过滤旋转水印。
- `tools/parse.py`：按「一、单选题 / 二、多选题 / 三、判断题」三节切段，分别取题干区与紧随其后的「参考答案」区，逐题号扫描拼装。
- `tools/build.py`：结构清洗（去重标号、判断题 A/B → T/F、空位规范化）、去重、按题块区间归章节，输出 `data/questions.json` 与校对表。

## 部署

仓库 `main` 分支根目录 → GitHub Pages，地址 <https://peng684596.github.io/lamp-2026-quiz/>。站点内所有路径均为相对路径，`https://<user>.github.io/<repo>/` 这类子路径可以直接工作；路由使用 hash（`#/chapters` 等），不需要服务器做 rewrite。

更新题库或改动代码后：

```bash
git add -A && git commit -m "更新题库" && git push
```

推送后 GitHub Pages 会在 1 分钟左右自动重新发布。

> 本机 git 全局配置里有一个指向 `127.0.0.1:23501` 的失效 GitHub 代理，该端口未监听会导致 `push` 报 `Failed to connect to github.com:443 over proxy`。本仓库已在自身 `.git/config` 里把 `http.https://github.com.proxy` 覆盖成本机可用的 `http://127.0.0.1:21630`；若换机器或代理变了导致推送失败，用 `git -c http.https://github.com.proxy= push`（直连）或改成当前可用的代理地址即可绕开。
